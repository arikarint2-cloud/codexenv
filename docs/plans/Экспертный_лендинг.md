# Спроектировать и запустить экспертный лендинг по консультациям Битрикс24

This ExecPlan is a living document. The sections `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` must be kept up to date as work proceeds.

If this repository contains `.agent/PLANS.md`, this plan must follow it.

## Purpose / Big Picture

Создать конверсионный лендинг для продажи экспертных консультаций по внедрению и развитию Битрикс24 в компании. После выполнения пользователь должен получить:
- Одностраничный сайт с чётким оффером, сегментацией услуг, кейсами, тарифами и FAQ.
- Форму заявки с базовой валидацией и понятным подтверждением отправки.
- Адаптивный интерфейс для desktop/mobile и наблюдаемое поведение при локальном запуске.

## Surprises & Discoveries

- Observation: В проекте отсутствуют исходники, манифесты зависимостей и существующий frontend-стек.
  Evidence: В корне репозитория обнаружены только `AGENTS.md`, `.agent/PLANS.md` и `.agent/AGENTS.md`.

- Observation: `.agent/PLANS.md` задаёт обязательную расширенную структуру ExecPlan и правило обновления документа по ходу работы.
  Evidence: Прочитан файл `.agent/PLANS.md`, включая секции `Required structure for an ExecPlan` и `Maintenance rule`.

- Observation: Контент из согласованного Google Doc доступен через Drive connector и содержит фактуру для лендинга (опыт с 2010 года, 150+ проектов, 45+ специалистов, TOP-10 Рейтинг Рунета 2025).
  Evidence: Выполнен `_fetch` по ссылке документа, получен текстовый контент документа.

- Observation: Browser Use успешно отрабатывает проверки интерактива лендинга после установки Node.js; ранее тест блокировался системной ошибкой доступа к `node.exe`.
  Evidence: После установки Node.js runtime `node_repl` запущен, тестовые действия и чтение статусов формы выполнены успешно.

- Observation: В форме заявок ошибка валидации могла восприниматься как «залипшая», если пользователь исправлял только e-mail, но другое поле всё ещё оставалось невалидным.
  Evidence: Пользовательский сценарий проверки выявил необходимость более точной и прозрачной обратной связи по каждому полю.

## Decision Log

- Decision: Для первой версии лендинга использовать статический frontend без фреймворка (`index.html`, `styles.css`, `script.js`) и без сборщика.
  Rationale: Репозиторий пустой; такой путь даёт быстрый запуск, низкий порог сопровождения и минимальные риски инфраструктуры на старте.
  Date/Author: 2026-05-08 / Codex

- Decision: Сразу проектировать лендинг как модульные секции с якорной навигацией (hero, услуги, процесс, кейсы, тарифы, FAQ, CTA, контакты).
  Rationale: Это повышает читаемость структуры, ускоряет A/B изменения и упрощает последующую интеграцию аналитики/CRM-форм.
  Date/Author: 2026-05-08 / Codex

- Decision: Контент и UI писать на русском языке с бизнес-ориентированным тоном и явными CTA.
  Rationale: Целевая задача сформулирована на русском и ориентирована на компании, выбирающие экспертизу по Битрикс24.
  Date/Author: 2026-05-08 / Codex

- Decision: Подчеркнуть в лендинге подтверждаемую экспертизу из Google Doc (год основания практики, объём проектов, размер команды и позицию в рейтинге) вместо абстрактных маркетинговых формулировок.
  Rationale: Это повышает доверие и усиливает B2B-оффер фактами.
  Date/Author: 2026-05-08 / Codex

- Decision: Улучшить UX валидации формы: показывать точечные сообщения ошибок по полям и автоматически очищать статус ошибки при новом вводе.
  Rationale: Пользователь сразу понимает, что именно исправлять, и не воспринимает старый статус как зависший.
  Date/Author: 2026-05-08 / Codex

## Validation and Acceptance

Валидация:
- Структурная проверка файлов:
```powershell
Get-ChildItem -Force
```
- Ручной функциональный smoke-тест в браузере:
  - Навигация скроллит к целевым секциям.
  - FAQ раскрывается/сворачивается.
  - Форма блокирует отправку при невалидных данных.
  - Форма показывает успешный статус при валидном вводе.
- Респонсив-проверка:
  - Mobile (~360px), tablet (~768px), desktop (>=1280px).

Критерии приёмки (observable behavior):
- Пользователь видит законченный лендинг с явным оффером и несколькими CTA.
- Нажатие на пункты меню и CTA приводит к ожидаемым секциям или форме.
- Форма заявки даёт понятную обратную связь в ошибочных и успешных сценариях.
- На мобильной ширине контент читаем и не ломает сетку.

## Idempotence and Recovery

- Создание файлов и папок с `-Force` идемпотентно (повторный запуск не ломает структуру).
- Изменения ограничены новыми frontend-файлами и могут быть повторно применены поверх пустого репозитория.
- Если разметка/стили сломаны, восстановление выполняется поэтапно: сначала `index.html`, затем `styles.css`, затем `script.js` с промежуточной браузерной проверкой.
- Деструктивные операции (удаление/перезапись несвязанных файлов) не используются.
